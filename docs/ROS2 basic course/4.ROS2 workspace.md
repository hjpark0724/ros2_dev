# 4. ROS2 작업 공간

## 1. 작업 공간이란?

ROS2 로봇을 개발할 때는 기능별 코드, 설정값, 스크립트 등 여러 파일을 한곳에서 관리해야 합니다. ROS2에서는 이러한 프로젝트 관련 파일을 저장하고 관리하는 디렉터리를 **작업 공간(workspace)** 이라고 합니다.

작업 공간은 개발 과정에서 사용하는 모든 데이터를 모아 두는 프로젝트의 최상위 디렉터리입니다.

## 2. 작업 공간 만들기

다음 명령으로 프로젝트 파일을 저장할 작업 공간과 소스 코드 디렉터리를 만듭니다. 여기서는 작업 공간 이름으로 ros2_ws를 사용합니다. 이름은 목적에 맞게 자유롭게 정할 수 있습니다.

~~~bash
mkdir -p ~/ros2_ws/src
~~~

생성한 작업 공간으로 이동합니다.

~~~bash
cd ~/ros2_ws
~~~

## 3. 작업 공간 빌드

작업 공간의 최상위 디렉터리에서 다음 명령을 실행합니다.

~~~bash
colcon build
~~~

빌드가 완료되면 작업 공간에 build, install, log 디렉터리가 생성됩니다. 작업 공간의 일반적인 구조는 다음과 같습니다.

~~~text
ros2_ws/
├── src/
├── build/
├── install/
└── log/
~~~

| 디렉터리 | 용도 |
| --- | --- |
| src | 패키지의 소스 코드와 스크립트를 직접 작성하거나 배치하는 공간입니다. |
| build | 빌드 과정에서 생성되는 중간 파일을 저장합니다. |
| install | 빌드된 실행 파일, 라이브러리, 설정 파일을 저장합니다. |
| log | 빌드와 실행 과정에서 발생하는 경고, 오류, 정보 로그를 저장합니다. |

대부분의 개발 작업은 src 디렉터리에서 진행합니다. 패키지를 빌드한 뒤에는 install 디렉터리의 결과물을 실행합니다. build와 log 디렉터리는 주로 빌드 문제를 확인할 때 사용합니다.

작업 공간 이름과 개수는 제한되지 않습니다. 예를 들어 로봇이나 프로젝트별로 별도의 작업 공간을 만들 수 있습니다.

~~~text
ros2_ws_a/  # 로봇 A 개발
ros2_ws_b/  # 로봇 B 개발
ros2_ws_c/  # 로봇 C 개발
~~~

이는 통합 개발 환경에서 여러 프로젝트를 독립적으로 관리하는 것과 같습니다.

## 4. 작업 공간 환경 설정

작업 공간을 빌드한 뒤에는 시스템이 해당 작업 공간의 패키지와 실행 파일을 찾을 수 있도록 환경 설정 스크립트를 불러와야 합니다.

현재 Zsh 터미널에서만 적용하려면 작업 공간 최상위 디렉터리에서 다음 명령을 실행합니다.

~~~zsh
source install/setup.zsh
~~~

모든 새 Zsh 터미널에서 자동으로 적용하려면 다음 명령으로 ~/.zshrc에 추가합니다.

~~~zsh
echo "source ~/ros2_ws/install/setup.zsh" >> ~/.zshrc
source ~/.zshrc
~~~

> **참고:** ~/.zshrc에는 ROS2 Jazzy 기본 환경을 먼저 불러오는 source /opt/ros/jazzy/setup.zsh 설정이 있어야 합니다. 작업 공간 설정은 그 아래에 추가해야 합니다.

이제 작업 공간 생성, 빌드, 환경 설정이 완료되었습니다.
