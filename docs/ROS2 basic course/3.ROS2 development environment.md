# 3. ROS2 개발 환경 구성

기본적인 ROS2 프로그램은 텍스트 편집기로도 작성할 수 있지만, 개발 효율을 높이려면 통합 개발 환경과 터미널 도구를 함께 사용하는 것이 좋습니다. 이 장에서는 VS Code, Zsh 터미널, Git의 기본 사용 환경을 구성합니다.

## 1. VS Code 개발 환경

브라우저에서 **VS Code**를 검색한 뒤, 사용하는 플랫폼에 맞는 설치 파일을 내려받아 설치합니다.

ROS2 개발 시에는 코드 작성과 탐색, 디버깅, Git 작업을 편리하게 하기 위해 필요한 확장 기능을 설치하는 것이 좋습니다. 예를 들면 다음과 같습니다.

- C/C++ 확장 기능
- Python 확장 기능
- ROS 확장 기능
- Git 관련 확장 기능

VS Code의 통합 터미널도 Zsh를 사용하도록 설정하면, 일반 터미널과 동일하게 ROS2 Jazzy 환경을 사용할 수 있습니다. ~/.zshrc에 다음 설정이 있어야 합니다.

~~~zsh
source /opt/ros/jazzy/setup.zsh
~~~

## 2. 터미널 사용

ROS2 개발에서는 여러 노드와 도구를 동시에 실행하므로 터미널을 자주 사용합니다. 여러 창과 분할 화면을 편리하게 관리하려면 Terminator를 사용할 수 있습니다.

### 2.1. Terminator 설치

~~~bash
sudo apt install terminator
~~~

### 2.2. Terminator 실행

기본 터미널은 다음 단축키로 열 수 있습니다.

Ctrl + Alt + T

Terminator를 설치했다면 애플리케이션 목록에서 **Terminator**를 실행하거나, 터미널에서 다음 명령을 실행합니다.

~~~bash
terminator
~~~

## 3. Git 사용

협업과 버전 관리를 위해 Git을 사용합니다. Git은 프로젝트의 변경 사항을 스냅샷으로 기록하고, 이전 상태와 비교하거나 복원할 수 있는 무료 오픈 소스 분산 버전 관리 시스템입니다.

### 3.1. Git 설치

~~~bash
sudo apt install git
~~~

설치가 끝나면 사용자 정보도 설정합니다.

~~~bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
~~~

### 3.2. 기본 Git 작업

Git에서는 다음 영역을 주로 사용합니다.

| 용어 | 설명 |
| --- | --- |
| 작업 공간(working tree) | 현재 파일을 편집하는 영역 |
| 스테이징 영역(staging area) | 다음 커밋에 포함할 변경 사항을 준비하는 영역 |
| 로컬 저장소(local repository) | 커밋이 저장되는 로컬 Git 저장소 |
| 원격 저장소(remote repository) | GitHub 등 네트워크에 있는 공유 저장소 |

새 프로젝트에서 Git 저장소를 만들고 첫 변경 사항을 기록하는 기본 흐름은 다음과 같습니다.

~~~bash
git init
git add .
git commit -m "Initial commit"
~~~

- git init: 현재 디렉터리를 Git 저장소로 초기화합니다.
- git add .: 현재 디렉터리의 변경 사항을 스테이징 영역에 추가합니다.
- git commit -m "메시지": 스테이징 영역의 변경 사항을 로컬 저장소에 커밋합니다.

### 3.2.1. 저장소 생성 명령

| 명령 | 설명 |
| --- | --- |
| git init | 현재 디렉터리에 새 Git 저장소를 만듭니다. |
| git clone URL | 원격 저장소를 복제하여 프로젝트를 내려받습니다. |

### 3.2.2. 변경 사항 기록 및 수정

| 명령 | 설명 |
| --- | --- |
| git add 파일 | 파일을 스테이징 영역에 추가합니다. |
| git status | 수정된 파일과 스테이징 상태를 확인합니다. |
| git diff | 작업 공간과 스테이징 영역의 차이를 확인합니다. |
| git commit -m "메시지" | 스테이징 영역의 변경 사항을 로컬 저장소에 커밋합니다. |
| git reset | 커밋 또는 스테이징 상태를 되돌립니다. |
| git rm 파일 | 파일을 작업 공간과 스테이징 영역에서 제거합니다. |
| git mv 기존 새이름 | 파일을 이동하거나 이름을 변경합니다. |
| git checkout 브랜치 | 브랜치를 전환합니다. |
| git switch 브랜치 | 브랜치를 전환합니다. Git 2.23부터 제공됩니다. |
| git restore 파일 | 파일의 변경 사항을 복원합니다. Git 2.23부터 제공됩니다. |

### 3.2.3. 커밋 기록 확인

| 명령 | 설명 |
| --- | --- |
| git log | 커밋 기록을 확인합니다. |
| git blame 파일 | 파일의 각 행을 마지막으로 수정한 커밋과 작성자를 확인합니다. |

### 3.2.4. 원격 저장소 작업

| 명령 | 설명 |
| --- | --- |
| git remote | 원격 저장소 설정을 확인하거나 관리합니다. |
| git fetch | 원격 저장소의 변경 사항을 내려받되 병합하지는 않습니다. |
| git pull | 원격 저장소의 변경 사항을 내려받아 현재 브랜치에 병합합니다. |
| git push | 로컬 커밋을 원격 저장소에 업로드합니다. |

Git 명령의 자세한 사용법은 다음 명령으로 확인할 수 있습니다.

~~~bash
git --help
~~~
