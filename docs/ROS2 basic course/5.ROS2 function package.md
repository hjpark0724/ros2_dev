# 5. ROS2 기능 패키지

## 1. 기능 패키지란?

로봇에는 주행 제어, 시각 인식, 자율 주행처럼 여러 기능이 있습니다. 모든 기능의 소스 코드를 하나의 프로젝트에 모을 수도 있지만, 다른 사람과 일부 기능만 공유하거나 유지보수하려면 코드가 서로 얽혀 관리하기 어려워집니다.

ROS2는 기능별 코드를 **패키지(package)** 로 분리합니다. 패키지 단위로 기능을 구성하면 코드 간 결합도를 낮추고, 필요한 기능만 다른 프로젝트나 ROS 커뮤니티와 쉽게 공유할 수 있습니다. 패키지는 ROS 소프트웨어의 재사용성을 높이는 핵심 단위입니다.

## 2. 기능 패키지 만들기

ROS2 패키지는 ros2 pkg create 명령으로 만들 수 있습니다.

~~~bash
ros2 pkg create <패키지_이름> --build-type <빌드_유형> --dependencies <의존성> --node-name <노드_이름>
~~~

| 항목 | 설명 |
| --- | --- |
| pkg | 패키지 관련 기능을 사용합니다. |
| create | 새 패키지를 생성합니다. |
| 패키지_이름 | 생성할 패키지 이름입니다. 필수 항목입니다. |
| build-type | 패키지의 빌드 방식을 지정합니다. C++ 패키지는 ament_cmake, Python 패키지는 ament_python을 사용합니다. |
| dependencies | 패키지가 사용하는 의존성을 지정합니다. C++ 패키지는 rclcpp, Python 패키지는 rclpy를 포함해야 합니다. |
| node-name | 생성할 기본 실행 노드의 이름입니다. 지정하면 관련 소스 파일과 설정 파일이 함께 생성됩니다. |

### 2.1. C++ 패키지 생성

먼저 작업 공간의 src 디렉터리로 이동합니다.

~~~zsh
cd ~/ros2_ws/src
~~~

다음 명령으로 C++ 예제 패키지를 생성합니다.

~~~zsh
ros2 pkg create pkg_helloworld_cpp --build-type ament_cmake --dependencies rclcpp --node-name helloworld
~~~

### 2.2. Python 패키지 생성

다음 명령으로 Python 예제 패키지를 생성합니다.

~~~zsh
ros2 pkg create pkg_helloworld_py --build-type ament_python --dependencies rclpy --node-name helloworld
~~~

> **참고:** 패키지 이름은 일반적으로 소문자, 숫자, 밑줄을 사용합니다. 패키지를 생성한 뒤에는 src 디렉터리 안에 새 패키지 폴더가 만들어집니다.

## 3. 패키지 빌드

패키지의 소스 코드를 작성하거나 수정한 뒤에는 작업 공간 최상위 디렉터리에서 빌드합니다.

~~~zsh
cd ~/ros2_ws
colcon build
~~~

특정 패키지만 빌드하려면 --packages-select 옵션을 사용합니다.

~~~zsh
colcon build --packages-select pkg_helloworld_cpp pkg_helloworld_py
~~~

빌드가 완료되면 현재 Zsh 터미널에 작업 공간 환경을 적용합니다.

~~~zsh
source install/setup.zsh
~~~

새 Zsh 터미널에도 작업 공간을 자동으로 적용하려면, 4장에서 설정한 것처럼 ~/.zshrc에 다음 항목을 추가합니다.

~~~zsh
source ~/ros2_ws/install/setup.zsh
~~~

## 4. 기능 패키지가 포함된 작업 공간 구조

패키지를 만든 뒤 ROS2 작업 공간은 일반적으로 다음과 같은 구조를 가집니다.

~~~text
ros2_ws/
├── build/                 # 빌드 중 생성되는 중간 파일
├── install/               # 빌드 결과물과 실행 파일
├── log/                   # 빌드와 실행 로그
└── src/                   # 기능 패키지 소스 코드
    ├── pkg_helloworld_cpp/
    │   ├── package.xml
    │   ├── CMakeLists.txt
    │   ├── include/
    │   └── src/
    └── pkg_helloworld_py/
        ├── package.xml
        ├── setup.py
        ├── setup.cfg
        ├── resource/
        ├── test/
        └── pkg_helloworld_py/
~~~

### 4.1. C++ 패키지 구성

| 항목 | 설명 |
| --- | --- |
| package.xml | 패키지 이름, 버전, 작성자, 라이선스, 의존성 등 패키지 정보를 정의합니다. |
| CMakeLists.txt | 소스 파일, 의존성, 빌드 대상 등 CMake 빌드 규칙을 정의합니다. |
| src | C++ 소스 파일을 저장합니다. |
| include | 헤더 파일을 저장합니다. |
| msg | 사용자 정의 메시지 인터페이스 파일을 저장합니다. |
| srv | 서비스 인터페이스 파일을 저장합니다. |
| action | 액션 인터페이스 파일을 저장합니다. |

### 4.2. Python 패키지 구성

| 항목 | 설명 |
| --- | --- |
| package.xml | 패키지 정보와 의존성을 정의합니다. |
| setup.py | Python 패키지의 설치와 빌드 설정을 정의합니다. |
| setup.cfg | Python 패키지의 기본 설정 파일입니다. |
| resource | 패키지 리소스 정보를 저장합니다. |
| test | 테스트 관련 파일을 저장합니다. |
| 패키지와 같은 이름의 디렉터리 | Python 소스 파일을 저장합니다. |

### 4.3. 선택적으로 추가하는 디렉터리

C++ 패키지와 Python 패키지 모두 프로젝트 목적에 따라 다음 디렉터리를 추가로 만들 수 있습니다.

| 디렉터리 | 용도 |
| --- | --- |
| launch | 여러 노드를 실행하기 위한 Launch 파일을 저장합니다. |
| rviz | RViz2 설정 파일을 저장합니다. |
| urdf | 로봇 모델 파일을 저장합니다. |
| params | 파라미터 파일을 저장합니다. |
| world | 시뮬레이션 환경 관련 파일을 저장합니다. |
| map | 내비게이션에 사용할 지도 파일을 저장합니다. |

이 디렉터리 이름은 필요에 맞게 변경하거나 새 디렉터리를 추가할 수 있습니다.
