# 13. ROS2 분산 통신

### 1. 개념

분산 통신은 네트워크로 연결된 서로 다른 장치의 ROS2 노드가 데이터를 교환하는 방식입니다. ROS2는 DDS 미들웨어를 사용하며, 같은 네트워크와 같은 `ROS_DOMAIN_ID`를 사용하는 노드는 자동으로 서로를 발견하고 통신합니다. 기본 도메인 ID는 `0`입니다.

```mermaid
flowchart LR
    A[호스트 A<br/>talker] -->|DDS 토픽| N[같은 네트워크<br/>ROS_DOMAIN_ID = 6]
    N --> B[호스트 B<br/>listener]
```

### 2. 기본 분산 통신

두 장치를 같은 Wi-Fi 또는 라우터에 연결하고 동일한 ROS2 버전을 설치합니다. Windows 가상 머신은 네트워크 어댑터를 브리지 모드로 설정하면 호스트와 같은 네트워크에 연결됩니다.

호스트 A에서 발행자 노드를 실행합니다.

```bash
ros2 run demo_nodes_py talker
```

호스트 B에서 구독자 노드를 실행합니다.

```bash
ros2 run demo_nodes_py listener
```

구독자 터미널에 발행자의 메시지가 표시되면 다중 장치 통신이 성공한 것입니다.

### 3. `ROS_DOMAIN_ID`로 그룹 나누기

같은 네트워크에 여러 ROS2 시스템이 있을 때는 도메인 ID로 그룹을 나눌 수 있습니다. **같은 도메인 ID**의 노드만 서로 발견하고 통신합니다.

두 장치의 `~/.bashrc`에 같은 값을 설정합니다.

```bash
echo "export ROS_DOMAIN_ID=6" >> ~/.bashrc
source ~/.bashrc
```

호스트 A에서는 발행자, 호스트 B에서는 구독자를 실행합니다.

```bash
ros2 run demo_nodes_py talker
```

```bash
ros2 run demo_nodes_py listener
```

서로 다른 도메인 ID를 설정하면 두 장치는 통신하지 않습니다.

### 4. turtlesim 분산 제어 예제

같은 도메인에 속한 두 장치에서 다음 노드를 각각 실행합니다.

호스트 A:

```bash
ros2 run turtlesim turtlesim_node
```

호스트 B:

```bash
ros2 run turtlesim turtle_teleop_key
```

호스트 B의 키보드 명령이 토픽을 통해 호스트 A의 거북이 시뮬레이터로 전달됩니다.

### 5. 도메인 ID 사용 시 주의사항

- 여러 플랫폼의 호환성을 위해 `ROS_DOMAIN_ID`는 `0`부터 `101` 사이를 권장합니다.
- 도메인 하나에는 최대 120개 노드를 권장합니다.
- 도메인 ID가 `101`이면 운영체제 예약 포트 때문에 최대 54개 노드만 사용할 수 있습니다.

### 6. DDS 도메인 ID 계산 개요

DDS는 TCP/IP 또는 UDP/IP 포트를 사용합니다. 기본적으로 도메인 하나는 250개 포트를 차지하고, 노드 하나에는 두 포트가 필요합니다. 따라서 일반적인 도메인의 이론상 최대 노드 수는 다음과 같습니다.

```text
(250 - 10) / 2 = 120
```

운영체제 예약 포트 범위가 플랫폼마다 달라, Linux에서는 일반적으로 `0–101` 또는 `215–231`, Windows와 macOS에서는 `0–166` 범위를 사용할 수 있습니다. 여러 플랫폼을 함께 쓸 때는 `0–101` 범위를 사용합니다.
